MỤC TIÊU
--------
Thêm vào hệ thống GymShark 2 nhóm chức năng:
1. Quản lý thiết bị & dụng cụ tập (Equipment & EquipmentMaintenance)
2. Quản lý nước uống / bán lẻ tại quầy gym (Retail POS)

Hai nhóm này chạy độc lập nhưng đều gắn vào hệ thống báo cáo (Reports) và sidebar admin hiện có.

A1. Database (Prisma Schema) — Thêm 2 model mới
------------------------------------------------
File: backend/prisma/schema.prisma

Model Equipment:
- id: String @id @default(uuid())
- code: String @unique (mã thiết bị, vd: EQ-01)
- name: String (tên thiết bị)
- type: String (CARDIO / WEIGHT / FREESTYLE / GROUP_CLASS)
- status: String (AVAILABLE / INACTIVE / MAINTENANCE / BROKEN)
- capacity: Int? (sức chứa, chỉ dùng cho dụng cụ nhóm)
- createdAt, updatedAt: DateTime

Model EquipmentMaintenance:
- id: String @id @default(uuid())
- equipmentId: String @db.NVarChar(100)
- equipment: Equipment @relation(fields: [equipmentId], references: [id], onDelete: Cascade)
- status: String (PENDING / IN_PROGRESS / COMPLETE / CANCELLED)
- startDate: DateTime
- endDate: DateTime?
- description, notes: String?
- createdAt, updatedAt: DateTime

Relation ngược: Equipment.maintenance -> EquipmentMaintenance[]
Index: @@index([status]) trên cả 2 model.

B1. Database (Prisma Schema) — Thêm 7 model mới
------------------------------------------------
File: backend/prisma/schema.prisma

Model ProductCategory:
- id, name(@unique), label(ví dụ: "Nước uống"), sortOrder

Model Product:
- id, sku(@unique), name, categoryId, unit("chai"/"hộp"/"cái"), salePrice, costPrice?, imageUrl?, isActive
- Relation: category -> ProductCategory, inventory -> Inventory?, saleItems -> SaleItem[]

Model Inventory:
- id, productId(@unique), quantity, lowStockThreshold, location?, lastStockInAt?, updatedAt

Model StockIn:
- id, code(@unique), supplier?, note?, createdById, createdAt
- Relation: items -> StockInItem[], createdBy -> User

Model StockInItem:
- id, stockInId, productId, quantity, unitCost

Model Sale:
- id, code(@unique), memberId?, staffId, paymentId(@unique)?, invoiceId(@unique)?, subtotal, discount, total, note, createdAt
- Relation: items -> SaleItem[], member -> Member?, staff -> User

Model SaleItem:
- id, saleId, productId, quantity, unitPrice, lineTotal

B3. Danh sách API Endpoints (retail.controller.ts)
---------------------------------------------------
GET    /retail/products          -> Danh sách sản phẩm (filter category, active, search)
POST   /retail/products          -> Tạo sản phẩm mới
PATCH  /retail/products/:id      -> Cập nhật sản phẩm (giá, tên, status...)
GET    /retail/inventory         -> Danh sách tồn kho + cờ low-stock
POST   /retail/stock-in          -> Tạo phiếu nhập kho (tăng tồn kho)
GET    /retail/stock-in          -> Lịch sử nhập kho
POST   /retail/sales             -> TẠO ĐƠN BÁN POS (quan trọng nhất, xem B4)
GET    /retail/sales             -> Lịch sử bán hàng
GET    /retail/sales/:id         -> Chi tiết một đơn bán
POST   /retail/sales/:id/refund  -> Hoàn tiền / Trả hàng
GET    /retail/reports           -> Báo cáo bán lẻ (doanh thu, top SP...)
GET    /retail/reports/top       -> Top sản phẩm bán chạy

B4. Tích hợp Payment & Invoice hiện có
---------------------------------------
File: backend/src/modules/retail/retail.service.ts (hàm createSale)

Luồng tạo đơn bán (transaction):
1. Tạo Sale record (code, staffId, memberId? nếu có hội viên)
2. Tạo SaleItem[] cho mỗi sản phẩm (quantity, unitPrice, lineTotal)
3. Tính subtotal, discount, total
4. Tạo Payment:
   - amount = total
   - method = CASH (mặc định) hoặc từ DTO
   - status = PAID nếu CASH, PENDING nếu BANK_TRANSFER/MOMO/VNPAY
5. Tạo Invoice:
   - invoiceNumber tự sinh (INV-YYYY-NNNNNN)
   - subtotal, discount, total, status = ISSUED (PAID nếu thanh toán ngay)
6. Trừ Inventory.quantity (nếu thanh toán thành công / PAID)
7. Kiểm tra low-stock sau khi trừ → nếu <= lowStockThreshold, tạo Notification cảnh báo

File: backend/src/modules/payments/payments.service.ts (tùy chọn)
- Khi confirm Payment, nếu liên kết Sale thì đảm bảo Sale.total khớp.
